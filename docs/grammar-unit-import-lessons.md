# Grammar Unit 导入问题记录

本文件记录结构化导入中已经确认的问题、原因、修复和防回归方法。执行 `$grammar-unit-import` 或 `$grammar-unit-validate` 时必须先阅读；遇到新的、已经定位并解决的问题时追加记录，不删除历史。

## 记录格式

每条记录包含：日期、范围、现象、原因、修复、防回归检查、状态。只记录有证据支持的原因；尚未解决的问题标记为 `待解决`，不能写成既定结论。

## 已解决问题

### 2026-09-08：正文模块首句缺失

- 范围：Unit 1 正文 B、C、D 等模块。
- 现象：原书模块标签后的概括句未显示，正文直接从例句开始。
- 原因：PDF 缓存包含文字，但区块范围和网页渲染没有稳定保留经过审核的 `heading`。
- 修复：正文区块独立保存 `heading` 和 `heading_range`，导入时确认该标题确实存在于来源区块，统一阅读器固定渲染它。
- 防回归检查：逐模块比较标签、模块首句和后续正文；导入器必须拒绝来源区块中找不到审核标题的 Unit。
- 状态：已解决。

### 2026-09-08：Unit 1 练习 1.4 动词提示词消失

- 范围：练习 1.4 第 3–14 题，例如第 14 题 `(He / start)`。
- 现象：数据库题干含提示词，但网页只显示句子和答案框，提示动词消失。
- 原因：提示词被保存为 `cue` 片段，前端只渲染 `text` 和 `input`；同时数据包把部分 `cue` 排在句子后缀之后。
- 修复：统一渲染器支持 `cue`；修正片段顺序；提示词继承正文排版。
- 防回归检查：按顺序重组 `text`、`input`、`cue` 后必须与完整 `prompt` 一致；每个答案槽必须恰好出现一次；浏览器核对页面上所有括号提示。
- 状态：已解决。

### 2026-09-08：答案文本的 PDF 字体运行造成单词粘连

- 范围：完整 `Key to Exercises` 导入。
- 现象：少量答案出现 `orAmy`、`o’clockinthe morning` 等缺少空格的文本，以及 a/b 子答案重复题号。
- 原因：PDF 将视觉上一行文字拆为多个字体运行，直接拼接会丢失运行边界的空格；部分子答案沿用相同题号。
- 修复：答案解析器按几何和字体运行边界保留必要空格，并合并同题号的 a/b 子答案。
- 防回归检查：全量答案必须保持 145 个 Unit、566 个练习小节、3941 条记录；空答案、重复业务键和内容哈希异常均为 0；再次导入必须全部为 unchanged。
- 状态：已解决。

### 2026-09-08：多 Unit 批量处理容易掩盖单元级错误

- 范围：连续导入多个 Unit。
- 现象：如果先生成或导入全部 Unit 再统一检查，早期 Unit 的内容、图片或答案关联错误会传播到后续工作。
- 原因：缺少强制的单元级验收门。
- 修复：主流程一次只处理一个 Unit；每完成一个 Unit 必须调用 `$grammar-unit-validate`，通过后才能继续。
- 防回归检查：批次报告逐 Unit 给出 PASS；任一 Unit 失败立即停止，后续 Unit 保持未修改。
- 状态：流程规则已建立。

### 2026-09-08：重新导入 Unit 会改变题目 ID

- 范围：已有 Unit 使用导入器的 `--replace` 流程。
- 现象：导入器先删除整个 Unit 再重新插入，导致 Unit、练习、题目、答案槽和答案记录全部获得新 ID；未来保存到数据库的用户草稿或作答历史会失去稳定关联。
- 原因：`--replace` 被实现为级联删除和全量重建，没有使用已有的稳定业务键更新记录。
- 修复：导入器改为逐层 upsert；练习、题目和答案槽按业务键更新并保留 ID，数据包中缺失的记录标记为 `is_active = false`；媒体增加 Unit 内唯一的 `asset_key`；正文区块按 heading 或 section label 更新。
- 防回归检查：每次重导已有 Unit 前后比较验证器输出的 `identity_sha256`；内容相同或仅修正文案时必须一致。另用数据库副本测试“移除题目后退役、恢复题目后以原 ID 重新激活”。
- 状态：已解决。

### 2026-09-08：新建草稿答案时延迟读取题目触发提前写库

- 范围：服务器端草稿批量保存。
- 现象：新建 `grammar_draft_answers` 后再通过关联延迟读取题目内容，SQLAlchemy 自动 flush 尚未填完的答案记录，触发内容哈希非空约束错误。
- 原因：ORM 的 lazy-load 查询会先执行 autoflush，而新对象的 `question_content_sha256` 尚未赋值。
- 修复：查询 active 答案槽时同时加载对应题目，在创建草稿答案前直接计算题目内容哈希，不再触发延迟加载。
- 防回归检查：独立数据库测试必须覆盖首次保存两个答案、修改一个答案、清空另一个答案，并确认内容哈希为 64 位 SHA-256。
- 状态：已解决。

### 2026-09-09：进行中的保存可能覆盖用户最后恢复的答案

- 范围：前端草稿异步保存队列。
- 现象：服务器原值为 A、保存 B 的请求尚未完成时，用户把输入改回 A；前端仅比较“最后已保存值”会误以为无需再保存 A，随后进行中的 B 请求完成并覆盖用户最终输入。
- 原因：去重逻辑没有区分服务器已确认状态与仍在排队或请求中的状态。
- 修复：只有当前 Unit 没有待处理保存时，才允许用最后已确认的服务器指纹去重；只要存在不同的待处理指纹，就将用户最新快照继续排入串行队列。
- 防回归检查：覆盖 A（服务器值）→ B（请求中）→ A（最终输入）的时序，最终一次请求必须保存 A；相同待处理指纹仍应去重。
- 状态：已解决。

### 2026-09-09：逐槽匹配会制造不存在的多空题答案

- 范围：正式提交的确定性判题。
- 现象：如果分别判断每个答案槽是否出现在任意可接受答案中，可能把 variant A 的第一个槽和 variant B 的第二个槽拼成教材从未接受的组合，并误判为正确。
- 原因：把完整答案变体错误地展开成每个槽相互独立的候选集合。
- 修复：每次只把用户所有槽与同一条 `grammar_answer_variants.values_json` 比较；只有完整组合命中才判正确。
- 防回归检查：测试至少包含两个双槽 variant，并断言跨 variant 混合槽值为 `incorrect`。
- 状态：已解决。
